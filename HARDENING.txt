Ultra Stalker Final V9.1.1
Runtime hardening baseline
==========================

Scope
- This file documents hardening that exists in the current Final V9.1.1 source tree.
- It is descriptive, not a claim that client-side code or embedded credentials are tamper-proof.

1. Network URL and redirect safety
- Shared netsec.py validates HTTP(S) URLs before urllib/http.client use.
- URLs with control characters, backslashes, missing hosts, malformed ports or disallowed userinfo are rejected.
- Credential-bearing metadata requests require HTTPS.
- Credential-bearing redirects are HTTPS-only and same-origin; cross-origin credential redirects and HTTPS downgrades are blocked.
- User-configured provider redirects may cross origin when needed for IPTV/CDN compatibility, but sensitive headers are removed on cross-origin redirects and HTTPS downgrade is blocked.

2. Remote artwork/media fetch safety
- Remote media targets are resolved and validated before connection.
- Loopback, link-local, multicast, unspecified and reserved destinations are blocked.
- Non-global/private destinations are rejected unless they belong to an explicitly trusted configured origin.
- The validated endpoint set is used by the media connection path to reduce DNS-rebinding/validation-to-connect gaps.

3. Local state / cache file safety
- Sensitive/private state paths use restrictive permissions where the current filesystem permits it (0600 files / 0700 private directories in the relevant writers).
- Important state/cache writes use temporary files plus fsync/replace-style atomic commits rather than in-place partial writes.
- Settings serialization intentionally removes credential fields so api_keys.conf credentials are not mirrored back into settings.json.

4. Credential handling
- User credentials live in /etc/enigma2/ultrastalker/api_keys.conf and override built-in defaults.
- Built-in TMDb/SubDL/SubSource defaults are stored as obfuscated client payloads, not readable plaintext; this is obfuscation only, not cryptographic secrecy.
- Legacy TMDb credentials found in settings are migrated to api_keys.conf before the legacy plaintext copy is removed when the filesystem allows the migration.

5. M3U/Xtream cache deserialization
- The fast M3U cache uses a restricted pickle Unpickler that rejects GLOBAL/class reconstruction.
- Only plugin-owned plain built-in container/scalar cache data is accepted by that path; arbitrary object reconstruction is not permitted.

6. Backup / restore integrity
- Current backup format uses a manifest with SHA-256 validation before restore/commit.
- Restore validates the archive/content before replacing live state and creates a safety backup in the normal UI workflow.
- Artwork/poster/backdrop cache is not treated as portable trusted configuration state.

7. Process execution / updater boundary
- Runtime source does not use shell=True or os.system().
- Where subprocesses are required (for example the updater), arguments are passed as an argv list rather than through a shell command string.
- QA/gate scripts may execute local trusted build metadata for validation; they are not network-facing runtime parsers.

8. Package / runtime hygiene expectations
- Release package must contain no pyc/pyo/__pycache__ or editor/backup junk.
- Free Portal and Free Xtream catalogues must be packaged as the intended catalogue data rather than generated empty placeholders.
- Legacy foreign-plugin branding/provenance strings remain a release-gate failure.

Known limits / explicit non-claims
- Obfuscated built-in API credentials can be recovered by a determined analyst with the package and runtime code.
- User-configured IPTV endpoints may intentionally use plain HTTP for provider compatibility; the plugin cannot add transport security that the provider does not offer.
- Host-side static checks do not replace physical Enigma2 receiver testing for decoder handoff, filesystem behavior, TLS stack differences, resource leaks or image-specific APIs.
